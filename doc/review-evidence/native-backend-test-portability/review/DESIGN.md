## Environment contract

The relevant consumer, accepted cuda_scheduler.cpp ParseDeviceWeightsOverride, reads std::getenv and returns the default empty override for either nullptr or an empty value. Existing helper calls supply only nullptr or the nonempty `0:100,1:1` override. Copying the original string before mutation is necessary because CRT mutation can invalidate getenv pointers.

Use _putenv_s so the CRT table read by std::getenv observes the change. A Win32 SetEnvironmentVariable-only replacement would not establish that property: Microsoft's [getenv documentation](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/getenv-wgetenv) describes the CRT environment copy. Validate through the actual consumer-facing std::getenv view, not merely a Win32 environment query.

Microsoft's [_putenv_s documentation](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/putenv-s-wputenv-s) specifies that an empty value removes the entry. Therefore value==nullptr maps correctly to removal via ""; native empty-value insertion/restoration is not general POSIX-equivalent behavior. Preserve POSIX empty-string semantics in its unchanged branch. Do not claim this helper can preserve a distinct inherited empty Windows entry through _putenv_s: it can become absent after restoration. That distinction is acceptable for this narrow consumer (both mean no override), but must remain explicit in tests/claims. Do not expand the patch into a global cross-platform environment abstraction.
