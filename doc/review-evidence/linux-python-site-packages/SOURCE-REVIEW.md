## Behavior and coverage

The original classifier excludes all descendants of stdlib, while the separate stdlib copier excludes its direct site-packages/dist-packages directories. The candidate admits only those two direct-child third-party layouts. It still excludes the stdlib root, real stdlib descendants and dynload root/descendants. Checking the first relative component rather than any ancestor named site-packages keeps misleading names beneath json or lib-dynload excluded. Existing sibling Debian dist-packages paths remain outside stdlib and retain their original handling.

Package/submodule normalization and standalone extension handling are unchanged. The subsequent outside-prefix refusal, real selected libpython ownership check, dependency relocation and staged import guard are unchanged. The patch does not silence or bypass the failing staged cryptography import.

The added19-line data-driven method exercises both nested layouts with an exact expected map containing cryptography and the standalone cffi extension, while including excluded stdlib/dynload and misleading nested-name inputs. By source reasoning, the old classifier returns an empty map for both subtests and fails that expected map. This is not an observed fail-before/pass-after result. The existing sibling-layout test and all existing assertions are retained. JPP already has conditional real-bundle integration coverage; this addition supplies deterministic path-layout coverage without requiring a particular host interpreter or native tools, so it is useful rather than a duplicate claim of integration coverage.
