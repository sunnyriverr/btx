## False-pass challenge and limits

A no-op Pause fails explicit metadata, phase and authorization checks. A Resume implementation that inserts a control through `Put` fails at the real cap; one that deletes ordinary objects fails unchanged count/table digest. A revocation moved before `Put` but committed outside the import transaction changes the `revoked` table and fails the full snapshot; moving it earlier inside the same transaction still rolls back and is not a repair. A permissive resume or resurrected permit fails replay/phase checks. Accidentally keeping only the original connection is excluded by the explicit unique-pointer reset.

A startup implementation that clears pause could still pass this component test because Service startup is intentionally absent. Cancellation of a genuinely running worker, denial of a completed queued private response, signed peer-driven count saturation, maintenance under the cap, 500 ms owner IPC behavior, physical SQLite/WAL/disk full and recovery are likewise not observed. Those are stated limitations, not reasons to repeat the unchanged component sequence. Existing JPP quota findings remain credited as known boundary controls.
