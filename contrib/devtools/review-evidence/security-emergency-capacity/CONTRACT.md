# Emergency persistence candidate

Baseline fd3a905f. Ordinary new-ID limit remains 16384. Only verified policy/revocation writers may append up to a fixed absolute total 16513. R129 budgets one replacement policy plus 128 revocation envelopes (policy principal maximum128); this is a finite shared allowance, not a guarantee to revoke every possible composition/evidence subject or reserve local priority. Valid peer revocations consume the same allowance. No R reset across restart/epoch changes. Exhaustion returns SEC_CONTROL_QUOTA with transaction rollback; ordinary new objects return SEC_OBJECT_QUOTA. Existing duplicates preserve merge/privacy behavior. No pruning or authorization changes.

The envelope budget is at most129MiB before SQLite/index/journal/WAL and other state overhead; SQLite max pages and real disk space remain independently limiting. There is no physical-space reservation. A successful emergency sequence does not restore ordinary capacity; containment and retention/archival remain separate. Old binaries can read the same schema but refuse fresh IDs at/above 16384, including controls; downgrade loses emergency admission.

Actual component fixture uses unsigned inert rows for count construction and genuine signed authority records at the production validation entry points. It does not reproduce network filling, a running worker, a guard restart, or physical disk-full. Candidate tests must use the same source against baseline and candidate, check late-write rollback, wrong/stale/expired authority, permitted below-cap work, ordinary-refusal, duplicate handling, negative evidence, boundary129/130, and connection reopen.
